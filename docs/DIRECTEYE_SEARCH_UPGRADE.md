# DIRECTEYE canonical search upgrade

The native RESP command `DIRECTEYE.RECORD.SEARCH <literal-keyword> <after-record-id-or-empty> <limit>` adds tenant-bound keyword search over existing QKV8 canonical rows. See [API reference](API_REFERENCE.md#104-directeye-authenticated-resp-commands) for the exact reply and limits. Existing `DIRECTEYE.RECORD.GET`, mutation, outbox, and feed wire shapes do not change. Clients must explicitly opt into SEARCH and rebuild against the updated public KV header if they call its C API.

The command reuses QKV8's existing SST key metadata index to locate tenant-prefix candidates; it then checks each record's current classification/SCI and matches the literal keyword against authorized live JSON. Provisioned KEYSTONE feed index identities and the AIMEM service identity cannot search, so their existing QKP capabilities are unchanged. There is **no new index to build or reindex**, and **stored data needs no migration**. An existing degraded SST index fails closed without compaction. Search checks the store's resident-key accounting and SST index capacity before enumeration, then returns `ERR DIRECTEYE search unavailable` (no IDs) if any bound is exceeded. A page is bounded to 32 IDs and 128-byte search terms; it is never silently truncated by a work limit. Pages are ordered by record ID and are not a transactionally stable snapshot during concurrent writes.

shortcut: 512 KiB resident memtable accounting, 1,048,576 GLOBAL SST metadata slots, at most 64 examined keys per search, and 256 KiB maximum value per SST row (checked in the record header before reading payload); upgrade to a tenant/label-aware search index when the global store exceeds 1,048,576 slots or a tenant exceeds the candidate ceiling. A store with 209,850 rows fits this ceiling with headroom (the index grows at 70% occupancy). The SST record header's classification/SCI is authorized before reading value bytes. The worst-case successful search examines at most 512 KiB of trie keys, 1,048,576 index slots under the store read lock, 64 candidate records of at most 256 KiB each, and retains at most 32 record IDs. Large or heavily populated stores may reject search even if the tenant has few rows; a degraded index or a large legacy canonical value also fails closed rather than repairing or returning incomplete results.

This is neither an inverted keyword index nor semantic/vector search. Native DIRECTEYE semantic search is **unimplemented**: there is no verified QIHSE semantic index serving these QKV8 canonical rows with the required live tenant/label authorization. An external KEYSTONE projection or outbox consumer does not change this native command's contract.

For validation, copy the source into an isolated directory and run `make test TEST_JOBS=32` there; never compile over running release binaries. `qihse_trinary_trie_foreach` now returns `bool`: C callers must check for incomplete enumeration on allocation failure; its callback and key ordering are unchanged. After pulling, run `make build-native` in a separate source/build checkout and rebuild C clients using the updated headers before a rolling service switch. Stored data needs no migration or reindex.
