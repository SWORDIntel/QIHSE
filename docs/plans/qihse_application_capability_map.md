# QIHSE application capability and guarantee map

**Status: working baseline, reviewed 2026-10-24.** This is a source-backed inventory for W11.0, not a product certification. “Target” budgets below are proposed acceptance gates; none are performance measurements. Revisit them with reproducible measurements in W11.2 and W11.6.

## How to read this map

The guarantee is the narrowest behavior implemented by the named API, not a guarantee of the whole database. A caller must not infer cross-model ACID, classified-data authorization, or durable acknowledgement merely because another API offers it. Public headers describe the contract; source and named tests are the evidence. Existing full-suite evidence is the 2026-10-24 run recorded in `ROADMAP.md` (aggregate, 72 gold workloads, and 48 standalone targets).

## Transactions and SQL

| Surface | Boundary and isolation | Acknowledgement, retry, recovery | Authorization and evidence |
|---|---|---|---|
| Generic transaction manager (`qihse_txn_*`) | In-memory manager; READ COMMITTED, REPEATABLE READ, SERIALIZABLE labels. SERIALIZABLE OCC works only for keys callers actually register. One transaction-local resource can publish atomically. The separate participant API is not durable coordinator logging. | Commit is a process-memory state transition/resource callback, not a WAL/fsync durability acknowledgement. Conflict/failure is returned; caller must replay. No restart recovery. Resource-attached savepoints and PREPARE are refused. | Manager itself has no principal parameter: callers must enforce identity at the access layer. `include/qihse_txn.h`; `src/tractable/qihse_txn.c`; `tests/test_txn.c`.
| Mutable table store / SQL UWP DML + SELECT | Each table transaction is a deep shadow; grouped commit publishes up to 16 distinct table shadows under all table write locks after validating every generation. UWP SQL enlists those shadows on DML. Autocommit SELECT supports one-table projection, verified AND predicates, LIMIT/OFFSET, and table READ ACL. Joins, aggregates, ordering, CTEs, expressions, and SELECT inside transactions fail closed. | Successful COMMIT means in-memory publish only. Conflicts abort; no automatic retry, WAL recovery, or durable commit ACK. Rollback discards the shadows. SQL savepoints and DDL in a transaction fail closed. Transactional SELECT visibility/isolation remains open. | UWP SQL/TXN/SCHEMA requires an active principal; DML checks WRITE, SELECT and schema reads require READ, schema mutation requires Operator, and AUTH identity swap during an open transaction is refused. Sources: `include/qihse_table_store.h`, `src/tractable/qihse_table_store.c`, `src/spinnaker/qihse_uwp_sql_txn_schema.c`; tests `test-table-store-txn`, `test-sql-dml-exec`, SQL completeness.
| PostgreSQL wire | Separate adapter; transaction controls and prepared statements are not implemented. | No transaction or retry/recovery guarantee exposed by this adapter. Unsupported controls return errors. | `src/spinnaker/qihse_pg_wire.c`; `docs/architecture/sql_engine.md`; `test-pg-wire-cluster`.

There is no current public guarantee that a checkout order, stock reservation, and outbound event commit together, or that a finding, blob reference, and provenance commit together. External payment and message delivery cannot be made atomic by a database transaction; use an explicit application workflow and idempotency strategy.

## Data model and access surfaces

| Model/API | Boundary and durability | Authorization boundary / supported use |
|---|---|---|
| KV (`qihse_kv_*`) | Single operation per key; user-aware CAS is atomic for that key. Export/import are whole-operation boundaries, not multi-key transactions. Persistence/WAL behavior depends on the owning engine and its sync path. | Classified writes require `qihse_kv_set_user`; context-free writes are unclassified-only. Reads, enumeration, export/import and replica snapshots have user-aware paths and fail closed. Replica cursor advance ACK follows cursor-file and directory fsync. `include/qihse_kv_store.h`; `test-kv-store`, backup and replication auth tests.
| Document store | Insert/query API; no transaction contract established here. | Insert has no principal or classification/SCI arguments; query has a user. Treat as unclassified/private-only until the lowest write/read boundary enforces labels. `include/qihse_document.h`; `test-document-store`.
| Column store | Append/aggregate/index operations; no cross-model transaction contract. | Append accepts labels but no actor; user-aware reads and aggregates exist. The write API cannot establish that the writer may assert the supplied label. Do not use for classified writes absent an enforcing adapter. `include/qihse_column.h`; `test-column-store`.
| Time series | In-memory insert, compression/flush helper, and aggregates; no public durable reopen or transaction contract established. | Insert accepts labels but no actor; range/aggregate reads accept a user. Label-setting authorization is not established by insert. `include/qihse_timeseries.h`; `test-timeseries`.
| Event stream | Append-only log with NONE, FDATASYNC, and FULL durability modes, flush, replay, and event-ID deduplication. ACK strength follows the configured mode; append APIs do not carry a user. | Append/read/iterate/replay and event existence APIs lack principal and labels. File permissions are not an authorization check. Use only for unclassified/private payloads or behind an enforcing boundary. `include/qihse_event_stream.h`; `test-event-stream`.
| Vector DB | In-memory/file-backed persistence modes, checkpoint/flush/compact and query modes; no cross-model transaction. Approximate candidate search (when selected) remains approximate even when candidates are reranked against FP32 vectors. | Generic ingestion accepts no principal or classification labels; query/get paths accept user context but metadata is not established by generic ingestion. Do not treat query-time user filtering as proof of safe classified ingestion. `include/qihse_vector_db.h`; `qihse_vector_db_persistence_test`.
| FTS | Derived search index with authorized persistence options; asynchronous/freshness coupling to authoritative data is not established as a transaction. | User-aware insertion checks target classification/SCI; legacy insertion is unclassified-only. Search visibility is applied before ranking/statistics so inaccessible documents do not affect those outputs. `include/qihse_fts.h`; `test-fts-persistence-auth`.
| AIMEM | Scoped memory, provenance/history, and embedding-backed recall APIs use KV-backed records; durable acknowledgement is separate from the documented KV sync fence. | Entry points require a user; writes inherit classification/SCI and reads resolve through authorized KV access. Built-in `builtin-lexical-256` embeddings are deterministic lexical features, not learned semantic embeddings. `include/qihse_ai_memory.h`, `src/spinnaker/qihse_ai_memory.c`; QH00/QH10 tests.
| Graph | In-memory graph/index operations with KV-layered persistence described in the header; no general transaction contract. | CRUD, traversal, enumeration and counts are context-free and carry no labels. Treat as unclassified/private-only absent an enforcing adapter. `include/qihse_graph_store.h`; `test-graph`.
| Blob | Content-addressed storage APIs require a user and bind tenant, classification and SCI metadata. | NULL is denied; use this API for protected binary payloads, subject to its API’s tenant/domain rules. It does not make a separate metadata or event write atomic. `include/qihse_blob.h`; `test-blob`.

The APIs marked unclassified/private-only are not authorized classified-data paths. This is a constraint, not a recommendation to rely on an outer caller check: QIHSE’s security invariant requires the authenticated context to reach the lowest data-retrieval or mutation layer.

## Replication, history, and recovery surfaces

| Surface | Actual guarantee | Limitation |
|---|---|---|
| Legacy WAL replication (`qihse_repl_*`) | Applies one validated WAL record to a bound KV store; refuses apply without a store; ordered in-memory replay watermark prevents duplicate application in-process. WAL has no classification/SCI, so classified writes fail closed. | Watermark is not restart-durable; callers needing durable exactly-once position must persist it. No authenticated durable ACK protocol is established by this API. `include/qihse_repl.h`; replication tests.
| KV backup (`qihse_backup_*`) | Authenticated full export/restore, integrity verification and incremental export. Full export/restore refuses partial visibility; incremental cursor is per visible sequence. | Sequence-zero records need a full baseline; a delta is not itself a full restore image. Recovery time depends on dataset and storage and has no current numeric SLO. `include/qihse_backup.h`; `test-backup-auth`, `test-incremental-export`.
| Federation range replication | Requires verified peer; bounded rounds (64 records); retains range cursor on transport failure and verifies digest before completion. | Caller/application must persist any cursor whose restart durability it needs; event dedup and range protocol do not make arbitrary application writes transactional. `include/qihse_federation_repl.h`; federation replication tests.
| Federation snapshot transfer | Verified peer; resumable sidecar; data and sidecar fsync precede ACK; truncates unacknowledged tail on recovery. Transfers bytes only. | Caller must authenticate backup verification and restore using an explicit principal; transfer completion is not restore completion. 8 GiB declared cap. `include/qihse_federation_snapshot_xfer.h`; snapshot transfer tests.
| CDC | In-memory LSN and callbacks delivered synchronously under a mutex. | No durable replay log, retry queue, backpressure contract, or principal parameter. Do not use as classified export. `include/qihse_cdc.h`; CDC tests.
| Read-replica pool | Health-checked round-robin host/port selection. | Not query dispatch; no lag/freshness or consistency bound and no principal propagation. `include/qihse_read_replica.h`.
| Consensus | Scoped, tick-driven quorum protocol with durable term/vote/fencing updates, snapshots and membership support. | Not a general transaction coordinator or a linearizable database read lease. Client session deduplication, pre-vote and leadership transfer are not established; transport authentication remains injected. `include/qihse_consensus.h`, `src/federation/qihse_consensus.c`.
| Task queue | Bounded task API with retry/timeout/TTL defaults. | No principal parameter; do not place classified payload/results here without an authenticated wrapper. `include/qihse_task_queue.h`.
| Controller SDK | Server-enforced commands and session-scoped watches; watch cursor can be resumed after reconnect. Optional QKP sealed transport; absent QKP, RESP is cleartext. | Generic command escape hatch can invoke any command permitted by server identity. Transport security and server authorization are separate controls. `include/qihse_controller.h`, `src/controller/qihse_controller.c`.

## Supported combinations and explicit gaps

- Supported today: a single KV operation with its per-operation authorization; bounded (16-table) UWP SQL DML transactions with in-memory atomic row-store publish and rollback; one-table autocommit SQL reads behind table READ ACL; user-authorized AIMEM operations; user-authorized FTS visibility; verified-peer resumable federation byte/range transfer; authenticated backup under a principal that can see the full exported/restored set.
- Unsupported today: cross-model atomic commit; durable SQL transaction commit/recovery; pgwire transactions; automatic conflict retries; transactional SQL read isolation; classified use through context-free model APIs; a global “all models are durable” acknowledgement; bounded replica staleness; durable CDC; and a numerical RTO/RPO guarantee for arbitrary datasets.
- Retry rule: only retry when the specific API reports a retryable conflict/failure and the operation is safe to replay. SQL generation conflict aborts; caller must replay the complete logical unit. Use stable operation IDs/CAS for idempotency where available. Do not infer that transport retry makes a multi-step workflow exactly once.
- Recovery point rule: RPO is zero only for a write whose documented success response follows the required durable flush/fsync fence. In-memory publish, in-memory cursors, NONE durability, and unacknowledged asynchronous replication do not qualify.

## Representative workloads and proposed acceptance budgets

These are initial planning gates, not achieved results. Dataset, seed, build flags, hardware, storage medium, durability mode, and load generator must be recorded with measurements. Run isolated workloads first, then run all four concurrently. Use the same data set and durability/auth settings when comparing builds.

| Workload | Fixed representative shape | Proposed acceptance gate |
|---|---|---|
| Commerce/inventory | 1,000,000 products and stock rows; each logical operation reads stock and writes order + reservation + durable outbound-event intent. | 1,000 completed logical operations/s for 30 min; p95 ≤50 ms, p99 ≤100 ms; zero oversells, duplicate logical orders, or partial order/reservation/event-intent states. Gate applies only after W11.1 implements the required atomic boundary.
| Fuzz finding/provenance | 1,000,000 findings with binary reproducer blobs and version/provenance references; 500 new findings/s sustained for 30 min. | p95 ingest ≤100 ms, p99 ≤250 ms; zero dangling references, missing blobs after acknowledged writes, or duplicate finding IDs. Gate applies only to the eventual supported transaction/ack contract.
| Agent memory retrieval | 1,000,000 scoped memory records, 768-dimensional provider embeddings, 100 authenticated queries/s for 30 min, mixed with 100 writes/s. | p95 query ≤250 ms, p99 ≤500 ms; zero unauthorized results. Report recall@10 separately against exact search; target recall@10 ≥0.95 for any approximate mode before enabling it by default.
| Combined contention | Run all above simultaneously, plus one vector-index rebuild and one backup/restore cycle; include a slow-storage profile. | Each workload remains within its absolute latency bound and no more than 2× its isolated p99; sustained process RSS ≤16 GiB and CPU ≤80% of available physical cores; queues remain bounded and overload is reported as backpressure/errors, never silent loss.

Recovery gates for the same 1,000,000-record reference data set: after process kill, restart and serve authorized reads within 60 seconds; verified full backup restore into an isolated instance within 300 seconds. Proposed RPO is 0 for acknowledged synchronous durable writes, measured by acknowledged operation IDs after kill/restart. For async replication, record the last acknowledged and last recovered sequence and report the measured loss window; no zero-RPO claim until a durable acknowledgement protocol proves it.

The numerical gates are intentionally testable targets rather than claims supported by the prior functional suite. The 2026-10-24 host run is useful functional evidence, but its nearly full root filesystem and mixed-purpose host make it unsuitable as the controlled performance baseline. W11.2 must select and record a controlled storage target before measurement; W11.6 owns combined failure proof.
